# 个人技术博客竞品研究

更新时间：2026-05-26

## 一、研究范围

本次调研把当前站点 `assertion.github.io` 视为一个工程师个人技术博客，而不是公司官网或内容媒体。竞品选择也围绕这个边界展开：个人长期写作、技术内容沉淀、工程师个人品牌、RSS/订阅分发、专题化知识库。

样本覆盖中文与英文两类站点。中文样本更接近本站读者语境，包括阮一峰的网络日志、酷壳、Draveness、Halfrost；英文样本用于观察个人品牌和订阅转化，包括 swyx、Will Larson 的 Irrational Exuberance，以及 The Pragmatic Engineer 这类从个人写作演进到媒体化 newsletter 的参考对象。

## 二、结论摘要

个人技术博客的竞争不主要发生在视觉设计，而发生在三个层面：读者一眼能否知道作者擅长什么，是否有可连续阅读的内容资产，以及读者离开后是否有再次回来的机制。当前站点具备轻量、干净、可长期维护的静态博客基础，但首页只呈现文章列表，关于页信息较旧，内容主题尚未形成明确系列，因此读者很难在首次访问时建立“为什么要订阅这个博客”的判断。

竞品的共同优势是把个人经验组织成稳定产品形态。阮一峰用“周刊”形成频率和心智，Draveness 把 Go 深度文章整理成书，Halfrost 把算法题解沉淀成 Cookbook，swyx 把文章、演讲、newsletter 和个人定位串成一条个人品牌路径，Will Larson 则用长期高密度写作加精选标记建立权威感。本站如果继续保持个人博客定位，最值得借鉴的不是复杂功能，而是明确定位、专题索引、精选内容和订阅入口。

## 三、本站现状

当前站点是 Jekyll 3.x GitHub Pages 博客，导航包含首页、分类、维基、关于和 RSS。内容结构简单，首页展示分页文章列表，分类页按 Jekyll categories 聚合，Wiki 页展示 `_wiki` collection 文档。这个架构维护成本低，也符合技术博客长期存档的需要。

从仓库内容看，站点主题包括读书笔记、云原生架构、Python 技术翻译、工程实践、企业软件公司历史观察等。内容跨度并不低，但外部读者不容易看到主线：`about` 页仍强调基础履历，首页没有作者定位或精选入口，`_posts/2023-09-14-atlassian-history.md` 这类企业软件观察内容缺少标准 front matter，可能无法像常规文章一样被 Jekyll 稳定纳入索引。与头部个人博客相比，本站当前更像私人知识存档，而不是面向读者的主题化出版物。

| 维度 | 当前状态 | 影响 |
| --- | --- | --- |
| 首屏定位 | 只有站点名和文章列表 | 新读者难以判断作者领域与订阅价值 |
| 内容资产 | 有文章、分类、Wiki，但缺少专题入口 | 老文章复用率偏低 |
| 内容频率 | 文章数量少，更新间隔长 | 难以形成固定访问习惯 |
| 信任线索 | 关于页有公司、教育、GitHub/微博 | 信息偏旧，缺少代表作和当前关注领域 |
| 分发机制 | 有 RSS | 缺少醒目的订阅说明和跨平台入口 |

## 四、竞品样本分析

### 1. 阮一峰的网络日志：用周刊建立稳定心智

阮一峰的网络日志最强的不是页面复杂度，而是“每周五发布”的可预期内容节奏。站点首页直接展示科技爱好者周刊和最新文章，周刊分类页也按年份沉淀了大量历史内容。读者知道什么时候回来，也知道回来能得到什么。

它的另一个关键优势是投稿和分发机制。科技爱好者周刊在 GitHub 开源，读者可以通过 issue 投稿，内容也同步到多个渠道。这让个人博客不只是作者单向输出，而变成一个轻量内容网络。对本站而言，不需要复制周刊规模，但可以学习“固定栏目 + 稳定格式 + RSS 明确订阅”的组合。

### 2. 酷壳：用观点密度和工程经验建立权威

酷壳的页面呈现并不精致，但文章具有很强的观点密度和工程经验标签。它常用具体技术问题切入，再延展到系统设计、团队协作、行业判断，读者记住的是“有经验的人讲透问题”的感觉。评论、评分和长文讨论也增强了社区感。

这种模式的门槛是内容必须有判断力。对本站来说，如果作者有阿里工程背景和企业软件观察积累，可以把“工程实践背后的取舍”作为差异化方向，而不是只做资料摘录。比如云原生、DevOps、平台工程、企业协作工具、Atlassian 类公司发展史，都适合从一线工程师视角写成观点型长文。

### 3. Draveness：把零散文章产品化为一本书

Draveness 的《Go 语言设计与实现》展示了个人技术博客产品化的典型路径。它不是简单按时间倒序堆文章，而是用书的结构组织内容：历史和现状、为什么写、写作理念、目标读者、主要内容、互动与勘误。这种结构让读者可以从任意章节进入，也能理解整套内容的学习路径。

对本站最有价值的启发是“专题页比文章页更能沉淀资产”。如果未来继续写云原生、企业软件或工程管理主题，可以先建立专题索引页，再把每篇文章挂到专题下。即使更新频率不高，读者也会感知到这是一个持续扩展的知识库，而不是几篇孤立文章。

### 4. Halfrost：垂直领域 + 工具化阅读体验

Halfrost 的旧站按年份列出大量技术文章，主题从 iOS、Weex、Go、HTTP/2、TLS 到 LeetCode 算法。它的核心竞争力不是单篇文章，而是长期在几个垂直领域持续积累，并把 LeetCode-Go 进一步做成 Cookbook、在线阅读、PDF、PWA、暗色模式等多形态产品。

这说明个人博客也可以有“轻产品”。本站不一定要做应用，但可以把 Wiki、读书笔记、企业软件案例整理成可下载或可连续阅读的资料包。例如“云原生架构读书笔记合集”“企业软件增长案例索引”“工程师读书路线”都比单篇文章更容易被收藏和传播。

### 5. swyx：个人品牌首页优先于文章归档

swyx 的首页先讲清楚作者是谁：Writer、Founder、Devtools Startup Advisor，并明确当前工作方向是 AI Engineer、Latent Space、DevRel/DevTools 等。随后才展示最新内容、newsletter、最受欢迎文章和演讲。这种结构服务的是个人品牌，而不仅是文章归档。

它的启发是：首页可以承担“作者说明书”的角色。读者第一次进入本站时，应当马上看到作者当前关注领域、代表文章、可订阅方式和社交入口。文章列表仍然重要，但可以排在定位信息之后。

### 6. Will Larson：长期写作 + 精选标记降低选择成本

Will Larson 的 Irrational Exuberance 文章数量极大，首页保留了强烈的时间线气质，同时用星标突出代表作。他的作者介绍也直接连接到书、newsletter、RSS 和热门文章集合。对于内容很多的个人博客，星标和集合页能显著降低读者选择成本。

本站目前文章数量不多，但仍然可以提前采用精选策略。与其让读者在分类里寻找，不如在首页或关于页放出“推荐从这里开始”的 3-5 篇文章。未来文章增加后，这个机制会比单纯时间倒序更稳定。

## 六、对本站的机会判断

本站不适合直接竞争“更新频率”和“内容数量”。阮一峰、Will Larson 这类站点已经建立了长期发布飞轮，新站或低频个人博客很难用同一维度追赶。更现实的方向是做窄：围绕作者背景，把工程实践、云原生/平台工程、企业软件产品观察、读书笔记串成一个清晰主题。

一个可行定位是：“工程师视角的企业软件与云原生观察”。这个定位能容纳现有内容：云原生架构白皮书读书笔记属于技术体系，Atlassian 历史属于企业软件案例，《Hit Refresh》属于科技公司转型和管理观察，Python/工程文章属于实践经验。它比泛泛的“个人博客”更容易让读者理解，也比单一技术栈更耐久。

## 七、建议优先级

### P0：先让新读者看懂本站

首页建议增加一段短定位，不超过 80 字，说明作者是谁、关注什么、读者能得到什么。文章列表上方可以放 3 个入口：推荐阅读、专题合集、订阅 RSS。这样不改变 Jekyll 技术栈，却能显著改善首次访问体验。

关于页也值得更新。当前关于页是简历式信息，适合建立真实性，但缺少当前关注方向和代表内容。建议加入“当前关注：云原生、平台工程、企业软件、工程效率”“推荐从这些文章开始”“联系与订阅”等段落。

### P1：建立专题索引，而不是只依赖分类

分类页是按文章 metadata 自动聚合，适合机器导航，但不适合作为策展入口。建议新增 3 个手工维护的专题页：

- 企业软件与产品增长：Atlassian、Microsoft、协作工具、开发者工具商业化。
- 云原生与架构：云原生白皮书、Service Mesh、Serverless、DevOps、平台工程。
- 工程师读书笔记：技术书、管理书、公司传记、读后总结。

这些专题页可以先很短，只要每个页面解释“为什么值得读”和“建议阅读顺序”。后续每新增一篇文章，只需把链接补进去。

### P2：把部分内容做成稳定栏目

如果作者希望恢复更新，建议从低负担栏目开始，而不是承诺高频周刊。可以采用月度或不定期格式，例如：

- 企业软件案例：一家公司、一个增长机制、一个工程启发。
- 架构读书笔记：一本白皮书/书/论文，提炼 5 个可迁移判断。
- 工程实践复盘：一个具体问题，写背景、约束、取舍、结果。
- 技术翻译与注释：保留原文价值，但加入自己的工程语境评论。

这些栏目天然适配当前内容，也能形成可预期结构。

### P3：增强订阅和分发

RSS 已存在，但导航中只是“订阅”链接。建议在首页、文章底部和关于页明确写出“通过 RSS 订阅更新”。如果未来有 newsletter、微信公众号、GitHub Discussions 或邮件列表，再逐步增加，不必一次做复杂。

对外传播时，专题页比单篇文章更适合作为入口。比如在 GitHub profile、社交媒体个人简介里放“企业软件观察合集”或“云原生读书笔记合集”，比放博客首页更有明确承诺。

## 九、衡量指标

个人博客不一定追求商业转化，但仍然需要知道内容是否有用。建议关注轻量指标：RSS 订阅点击、热门文章访问、专题页访问、外链引用、GitHub profile 或社交媒体带来的入口流量。如果不想引入复杂分析工具，也可以先通过 GitHub Pages/搜索引擎表现和读者反馈粗略判断。

更重要的是内容资产指标：是否有 3 个清晰专题，每个专题是否至少有 5 篇内容，首页是否有明确代表作，关于页是否能让陌生读者在 30 秒内理解作者可信度。对个人站点而言，这些比短期 PV 更能体现长期价值。
